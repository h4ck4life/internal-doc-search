⚙️ Configuration
500 – 5000 chars Max characters per chunk. Larger keeps more context; smaller gives tighter matches. Re-ingest after changing.
0 – 500 chars Characters shared between neighbouring chunks. Raise if answers get cut off at boundaries.
1 – 20 results Results returned per search query.
10 – 200 candidates Candidates fetched before the cross-encoder reranks them. Higher is more accurate but slower.
hard = filter · boost = score-blend hard hides off-label docs entirely; boost lets them surface lower in results.
0 – 1 How strongly a label match lifts a result score. Only applies in boost mode.
0 – 1 Hides results below this cross-encoder score. 0 shows everything.

API Endpoints (17) Open Swagger UI
GET/search?q=&limit=&label=Two-stage semantic search; multi-label (OR) with -prefix exclusion
GET/labelsList distinct labels (with URL counts)
GET/healthService readiness — Qdrant connectivity check
POST/ingestStart background re-crawl (409 if already running)
GET/ingest/statusCurrent crawl progress (running/total/chunks)
GET/docs-summaryURL count, chunk count, last crawl + file stats
GET/urlsList all configured crawl URLs with status
POST/urlsAdd new crawl URL (deep_crawl, deep_crawl_max_depth)
PUT/urls/{id}Update URL string, label, or deep crawl settings
DEL/urls/{id}Remove crawl URL and its vectors
POST/urls/{id}/recrawlRe-crawl a single URL in background
POST/filesUpload document (multipart: file + labels)
GET/filesList uploaded files with labels and chunk counts
DEL/files/{id}Delete file and its vectors from Qdrant
GET/configGet all configuration values
PUT/configUpdate configuration (label_match_mode: hard|boost, weight 0–1)
